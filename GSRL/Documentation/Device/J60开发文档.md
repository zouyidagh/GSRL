# J60 关节电机驱动开发文档

## 1. 概述 (Overview)

本文档记录了基于 GSRL 架构适配 **DeepRobotics J60** 关节电机的开发细节。
驱动逻辑已从官方开源代码 (`DeepRobotics-J60Motor-STM32`) 移植并重构为 C++ 类 `MotorJ60`。

## 2. 协议规范 (Protocol Specification)

通信波特率：**1 Mbps**

### 2.1 CAN ID 定义

J60 电机的 CAN ID 并非固定，而是包含指令信息的动态 ID：

$$ ID = (\text{CmdID} \ll 5) \ | \ \text{MotorID} $$

其中：
*   **MotorID**: 0 ~ 15 (4 bits)
*   **CmdID**: 指令类型 (6 bits)

常见 CmdID：
*   `CMD_DISABLE` (1)
*   `CMD_ENABLE` (2)
*   `CMD_CONTROL` (4) - 运动控制
*   `CMD_CLEAR_ERROR` (17)

### 2.2 数据帧定义 (Control Frame)

**Motion Command (CMD_CONTROL = 4, DLC = 8)**

采用小端模式 (Little-Endian) 打包：

| Byte | Data | Scale/Range | Note |
| :--- | :--- | :--- | :--- |
| 0 | Pos[7:0] | - | 16-bit P [-40, 40] rad |
| 1 | Pos[15:8] | - | |
| 2 | Vel[7:0] | - | 14-bit V [-40, 40] rad/s |
| 3 | Vel[13:8] \| Kp[1:0] | Vel(0-5 bit), Kp(6-7 bit) | Mixed Byte |
| 4 | Kp[9:2] | - | 10-bit Kp [0, 1023] |
| 5 | Kd[7:0] | - | 8-bit Kd [0, 51] |
| 6 | T[7:0] | - | 16-bit Torque [-40, 40] Nm |
| 7 | T[15:8] | - | |

### 2.3 反馈帧定义 (Feedback Frame)

电机返回 ID 通常为 `(CmdID << 5) | MotorID` 或 `(CmdID << 5) | (MotorID + 0x10)`（视固件版本而定）。
驱动中采用了宽松匹配逻辑：`RxID & 0x1F == MotorID` 或 `RxID & 0x1F == (MotorID | 0x10)`。

**解析逻辑 (开源对齐版)**

*   **Position (20-bit)**: `Data[0] | Data[1]<<8 | (Data[2]&0xF)<<16`
*   **Velocity (20-bit)**: `(Data[2]>>4) | Data[3]<<4 | (Data[4]<<12 & 0xFF00)`
*   **Torque (16-bit)**: `Data[5] | Data[6]<<8`
*   **Temperature**: `Data[7] >> 1` (Bit 0 为 Flag)

## 3. 使用说明 (Usage)

在 `GSRL` 框架中使用 `MotorJ60` 类：

### 3.1 初始化

```cpp
// 声明 PID
SimplePID::PIDParam param = { 10.0f, 0.0f, 500.0f, 10.0f, 0.0f };
SimplePID myPID(SimplePID::PID_POSITION, param);

// 声明电机 (ID=1)
MotorJ60 motor(1, &myPID);
```

### 3.2 启动序列

J60 电机需要显式的使能序列。推荐流程：

1.  **清除错误**: 调用 `motor.clearError()` 并发送数帧。
2.  **使能**: 调用 `motor.enable()` 并发送数帧（至少 10 帧）。
3.  **进入控制环**: 之后可连续发送控制指令。

```cpp
// 示例 (伪代码)
motor.clearError();
transmit(10_times); // 发送 CMD_CLEAR_ERROR

motor.enable();
transmit(20_times); // 发送 CMD_ENABLE

while(1) {
    motor.setControlParams(pos, 0, 0, kp, kd);
    motor.convertControllerOutputToMotorControlData();
    transmit(); // 发送 CMD_CONTROL
    delay(10ms);
}
```

### 3.3 状态机适配

驱动内部已去除了原有的 State-Block 逻辑，以完美适配开源代码的“无状态”发送模式。这意味着无论此时电机的反馈状态是什么，只要调用了 `setControlParams` 和 `convert`，驱动都会尝试构建 Motion 指令。这增强了在通信不稳定时的鲁棒性。
